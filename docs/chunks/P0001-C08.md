# Chunk P0001-C08 — `add --plugin`

**Goal:** `tack add SOURCE --plugin P…` adds a source that deploys plugins
(and, without `--skill`, only plugins), refusing what `sync` couldn't deploy
before anything is written, and `add` without `--plugin` on a plugin-only
repository says which plugins it offers. The TUI's add form takes plugins
too. That is delivery item D6, which D8 extends to plugins from other
repositories. Unit a is the P0001-C07 review's follow-ups: `outdated` and
the unpushed-edit check read git's file lists NUL-separated and without
rename detection (#46, #47).

## Kickoff notes

Unit a is mechanical but easy to get half right: every git command whose
output tack splits into paths gets `-z`, and the ones naming skills get
`--no-renames`; a test fixture must hold a name git quotes, or the test
passes with `-z` removed. Units b and c are D6: read design.md *Adding and
removing sources* (pinned at this cut) sentence by sentence. A plugin
refusal gives the reason `sync` gives for the same plugin, from code both
call, not a copy of its wording; a test holds the two together. Until D8,
a plugin from another repository is refused as `sync` reports it ("tack
doesn't deploy those yet"); D8 lifts that. The reviewer will check that
every refusal exits `2` with nothing written and a fresh clone removed,
the table's exact text, and that a `skills = []` source isn't refused for
having no skills directory.

## Units

### P0001-C08-a — git's file lists, whatever the names hold

**Build** (design.md *Tracking upstream*, *Auto-commit*'s last paragraph,
both pinned at this cut; fixes #46 and #47):

- Every git command whose output tack splits into file paths reads it
  NUL-separated (`-z`): `outdated`'s skills log, `_Tracked.commits`, and
  `sources.unpushed`. The commit header and its file list still have to be
  told apart; any framing that survives a name holding a newline will do.
- `outdated`'s skills diff and skills log, and `sources.unpushed`, run with
  `--no-renames` (the plugin commands already do), so a renamed skill is
  its old name removed and its new one added, and a file moved between
  skills touches both.

**Tests:** in `tests/test_outdated.py`, a commit whose only change under a
selected skill, and one under a selected plugin, is to a file named with a
double quote, a tab and a newline (one name each, or one name holding
all three): each commit listed and attributed. A skill renamed upstream
(`git mv skills/a skills/b`) under `"*"`: `a` removed, `b` added, the
commit attributed to both; under `skills = ["a"]`, the commit listed. In
`tests/test_sources.py`, an unpushed commit touching only such a file
reports its skill, and a file moved from skill `a` to skill `b` in one
reports both. Remove `-z` (or `--no-renames`) from each site in turn: a
test fails each time (review-checklist §1, §2).

**Done when:** those pass, and every existing `outdated`, `sources`,
`commit` and `doctor` test passes unchanged. (Checked at the cut,
brief-checklist §7: no fixture holds a name git quotes, and the one rename,
`test_doctor_skills`'s `git mv skills/b skills/b2`, is uncommitted, which
`uncommitted` already reads.)

### P0001-C08-b — `add --plugin` writes plugins and refuses what `sync` can't deploy

**Build** (design.md *Adding and removing sources*, the *(P0001)*
sentences; *Catalogs*; DEC-3, DEC-11):

- `edit.add` takes `plugins` (names). It writes `plugins = [...]` after
  `skills`, each name once in the order given; with plugins and no skills,
  it writes `skills = []`. With neither, the table is as before.
- With plugins and no skills, the source's skills aren't checked (no
  skills directory and none in it are both fine). With skills too, they are
  checked as now.
- Refusals (exit `2`, nothing written, a fresh clone removed), after the
  skills' and in this order: a broken catalog, with its error alone; the
  names the catalog doesn't have (saying whether the source has no catalog
  or naming the names its catalog lacks); each selected plugin `sync` would
  report as a `source` problem, with the reason `sync` gives: one tack
  can't deploy (`Undeployable.reason`), one from another repository (until
  D8), and one whose files can't be read (`plugins.files_hash`'s
  `Unreadable.reason`, so its copy would fail); each plugin another source
  already selects (DEC-11), naming that source. The undeployable and
  other-repository reasons come from one function that `sync`, `doctor`
  and `add` all call, not three wordings.
- A dry run of a git source checks no plugin, as it checks no skill. A path
  source's dry run checks both.

**Tests**, in `tests/test_edit.py`: the table for `--plugin a --plugin a b`
alone (`skills = []`), with `--skill`, and with `--subdir`, each
round-tripping through the manifest parser to the expected source; a path
source and a git source with no skills directory accepted with
`--plugin`. Each refusal (no catalog, a missing name, a broken catalog, an
undeployable plugin, one from another repository, one whose directory is
gone, one another source selects), for a path source and for a fresh git
clone: `UsageError`, `tree(home)` unchanged. For an undeployable plugin,
one from another repository, and one whose directory is gone, the
refusal's reason equals the `source` problem a `sync` dry run reports for
the same path source already in the manifest selecting it.
After an accepted add, the stand-ins show the plugin installed in both
agents (`claude plugin install a@tack`, `codex plugin add a@tack`). A dry
run of a git source with a name its catalog lacks: accepted, nothing
written.

**Done when:** those pass, and every existing `add` test passes unchanged.

### P0001-C08-c — the CLI, the no-skills refusal, the TUI form, and the docs

**Build** (design.md *Adding and removing sources*, *The TUI*'s `a`):

- `tack add … --plugin P…` (`metavar` `P`, `nargs="+"`, `action="extend"`,
  as `--skill`), passed to `edit.add`.
- Without `--plugin`, the two no-skills refusals (no skills directory;
  none in it) end with the plugins `--plugin` would accept from the
  source's catalog, sorted: those `sync` would deploy and no other source
  selects. With none (no catalog, a broken one, none deployable), the
  refusal is as before.
- The TUI's add form gains a plugins field after skills ("plugins to
  deploy, space-separated (default: none)"), split as the skills field is;
  the skills placeholder says its default is none when plugins are given.
- README.md and `skills/tack/SKILL.md`: `--plugin` and `skills = []`, the
  refusals, and a `tack add … --plugin` example line in the skill's command
  block (`test_the_skill_runs_real_commands` parses it).

**Tests:** the CLI passes `--plugin a b --plugin c` through (`test_cli`).
The no-skills refusal for a plugin-only repository lists exactly the
plugins `--plugin` would accept (an undeployable one and one another source
selects left out), and adding each listed name is then accepted; a source
with no catalog keeps the old message. A TUI pilot test fills the plugins
field and gets `plugins` in the dismissed fields, and the add runs with
them.

**Done when:** those pass, `tests/test_examples.py` and `test_skill.py`
pass, and README and the skill describe `--plugin`.
