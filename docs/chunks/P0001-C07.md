# Chunk P0001-C07 — `outdated` tracks plugins

**Goal:** `tack outdated` reports what upstream changed in a git source's
selected plugins (modified, added, removed, with versions at the pin and the
tip), lists the commits touching them, and `--diff` shows those changes;
`update` is shown to carry a plugin change through to Codex. That is
delivery item D5, which D7's Sources detail and D8's clone diffs build on.
Unit a is the C06 review's follow-up: `doctor` reports every plugin problem a
`sync` dry run reports (DEC-19, #44).

## Kickoff notes

Unit a is small but exact: read DEC-19 and design.md *`doctor` checks*
sentence by sentence. Its findings must agree with a `sync` dry run's plugin
problems, so a test runs both and compares; the reason for a plugin whose
files can't be read comes from the same code `plugins.update` uses, not a
copy of its wording. Units b and c are D5: read design.md *Tracking plugins
upstream* (rewritten at this cut) with DEC-20, and *Catalogs* for how a
catalog and a version are read. They read catalogs and `plugin.json` files
from git at a commit, a second reader beside `catalog.read` and
`catalog.files` on disk, so a test holds each to the disk reader. The
reviewer will check each change kind and version against the bullets, the
commit attribution (entry changes against the first parent), the `--json`
shape, and that a source selecting no plugins reads no catalog.

## Units

### P0001-C07-a — `doctor` reports every plugin problem `sync` would

**Build** (design.md *`doctor` checks*; DEC-19; fixes #44):

- A source finding (`not-synced`, warn) for each plugin `sync` would copy
  whose files can't be read: one in `plan.plugins`, in the source, and not
  kept for another reason (a collided name, or a recorded plugin whose
  source's catalog can't be read). At its directory, with the reason `sync`
  gives (`plugins.update`'s failure message, from code both share). Such a
  plugin gets no per-plugin state finding and isn't named by a harness's
  finding.
- A harness's `unavailable`: for a missing CLI when any selected plugin
  targets the harness (deployable or not, collided or not); for a failing
  `list` when `sync` runs that harness at all (`_involved`). Its `conflict`:
  when a selected plugin targets the harness or the record lists one there.
  Each names the plugins it stops that have no finding of their own, and
  when there are none says only what is wrong with the harness and what
  fixes it. Harness and order as before.
- README.md and `skills/tack/SKILL.md` (review extras): a plugin whose files
  can't be read, and that a harness's problem is reported wherever `sync`
  would report it.

**Tests**, in `tests/test_doctor_plugins.py`:

- Agreement with `sync`: for each case, every source is `ok` and `doctor`'s
  `name-collision`s (by name), its source findings other than lacked names
  (by path and plugin), and its per-harness `unavailable` and `conflict` (by
  harness) correspond one to one with a `sync.sync(cfg, dry_run=True)`'s
  `collision`, `source`, `agent` and `conflict` problems. Cases: a selected
  plugin whose directory is gone, installed and not yet installed; a foreign
  `tack` where only the record lists plugins; a failing `plugin list` in a
  harness only the record involves, and in one only tack's marketplace
  directory involves; a missing CLI only an undeployable plugin targets; a
  missing CLI a deployable plugin targets; a broken catalog; an undeployable
  plugin; a plugin from another repository; a collision.
- The unreadable plugin's finding: id, severity, path, and the reason the
  dry run's problem gives; installed or not, it is that one finding, with no
  per-harness state finding for the plugin.
- Each new harness finding's message names the harness and its fix, and one
  naming no plugin reads as such.

**Done when:** those pass, `test_state_findings_agree_with_status` and
`test_leftovers_agree_with_sync` pass unchanged, and the README and the
skill describe the new cases.

### P0001-C07-b — `outdated` reports changed plugins and their versions

**Build** (design.md *Tracking plugins upstream*, up to the commits bullet,
and the `--json` and text paragraph's plugin objects, `plugins_error` and
text lines; DEC-20):

- Reading a catalog at a commit: the same file precedence and parsing as
  `catalog.read` (via `catalog.parse`), from a git repository at a commit; a
  missing catalog is none, an unreadable or invalid one a `CatalogError`.
  Reading a plugin's file at a commit, for `catalog.version`.
- `outdated` for a `behind` source that selects plugins: the selected
  plugins (`"*"`: either end's catalog; a list: its names, one in neither
  catalog left out), each change (*modified* by entry, or by files under its
  directory at either end for a plugin in the source; *added*; *removed*),
  sorted by name, each with `version` `{"from", "to"}`. A source selecting
  no plugins reads no catalog and has `plugins` `[]`. A catalog broken at
  either end: no plugin changes, `plugins_error` its error (DEC-20).
- `SourceReport` gains `plugins` and `plugins_error` (null when there is
  nothing to say), so `--json` gives them; the text adds the plugin lines
  and "no selected skill or plugin changed" as the section says. A source
  selecting no plugins prints exactly what it printed before.

**Tests**, in `tests/test_outdated.py` on local git remotes:

- A file change under a plugin's directory, and an entry-only change (a
  description), each *modified*; a plugin whose entry moves its directory;
  a new plugin under `"*"` *added*, and not under a list that doesn't name
  it; a dropped one *removed*; an unselected plugin's change ignored; a
  plugin from another repository *modified* by a new `sha` and not by files.
- Versions: from `plugin.json` at each end, from the entry, `"from"` null
  for an added plugin and `"to"` null for a removed one.
- A catalog broken at the tip, and at the pin: `plugins` `[]`,
  `plugins_error` set, the skills still compared. A source with
  `plugins = []` whose catalog changed: no plugins, and no catalog read
  (review-checklist §1: break its catalog at the tip, and nothing changes).
- The reader at a commit equals `catalog.read` on the same tree, for a
  Claude Code catalog, a Codex one, both present, none, and a broken one;
  a version read at a commit equals one read from the checked-out
  directory.
- `--json` shape (the plugin object and `plugins_error`), and the text lines
  for each kind with and without versions.

**Done when:** those pass, and every existing `outdated`, `cli` and TUI test
passes unchanged.

### P0001-C07-c — Commits touching plugins, `--diff`, and `update`

**Build** (design.md *Tracking plugins upstream*, the commits and `--diff`
bullets and each commit's `plugins`; DEC-20):

- Each listed commit gains `plugins`, the selected plugins it touches,
  sorted; a commit touching only selected plugins is now listed too. A
  commit touches a plugin when it changes a file under its directory at the
  pin or the tip, or changes a catalog file and the plugin's entry differs
  from its first parent's (a catalog that can't be read at a commit having
  no entries). Merge commits touch nothing. With `plugins_error` set, no
  commit is attributed to a plugin.
- `--diff`: after the skills' diff, each changed plugin's, in name order:
  the diff under its directory at either end, then its entry's unified diff
  as the section gives it (headers, `/dev/null`, JSON indented two spaces in
  the catalog's key order).
- `update` needs no new code: a test shows a changed plugin file reaching
  Codex as a reinstall, and nothing run in Claude Code.
- README.md and `skills/tack/SKILL.md`: what `outdated` reports about
  plugins and the `--json` additions, and "upstream reports still track
  skills" removed (review extras).

**Tests:** a commit changing a plugin's file lists it; one changing only its
catalog entry lists it, and one changing another plugin's entry in the same
catalog doesn't; a commit that breaks the catalog and one that fixes it both
list the plugins whose entries they hide and restore; a merge lists
nothing; a commit touching a skill and a plugin lists both. `--diff` for a
file change, an entry change, an added and a removed plugin, limited to the
changed plugins. `update` after an upstream plugin change: Codex
`plugin add` again, the record's hash moved, no Claude Code command.

**Done when:** those pass, and the README's and the skill's examples
(`tests/test_examples.py`) still pass.

### What landed

**a — `doctor` reports every plugin problem `sync` would.**
`plugins.files_hash(directory)` returns a plugin's `tree_hash` or an
`Unreadable(reason)`, the message `plugins.update` reports for the plugin's
failure; `plugins.update` now calls it (and a shared `_failure` for a copy
that fails), and `status.plugin_digest` uses it for its None, so the reason
has one source. In `doctor/plugins.py`, `_kept` no longer treats "digest is
None" as kept: it holds a collided name, a plugin from another repository,
and a recorded plugin whose source's catalog can't be read; `_unreadable`
then hashes each plugin in `plan.plugins` with a directory that isn't kept
and gives the ones `sync` would fail to copy. Each is a `not-synced` source
finding at its directory ("plugin 'a' from 'one' can't be copied, so tack
leaves it as it is: <reason>"), gets no per-harness state finding, and isn't
named by a harness's finding; it joins the kept set for leftovers. A
harness's `unavailable` now comes for a missing CLI whenever a selected
plugin targets the harness, and for a failing `list` whenever `_involved`;
its `conflict` whenever a selected plugin targets it or the record lists
one there. With nothing of its own to name, the message reads "tack can't
manage <harness>'s plugins" with the same fix as before. Harness order and
per-harness order are unchanged. README and the skill describe both.

**b — `outdated` reports changed plugins and their versions.**
`git.cat(repo, commit, path)` reads an object at a commit through
`git cat-file --batch --follow-symlinks` (bytes, symlinks inside the tree
followed as a checkout would, `missing` for nothing or a path through a
file). `catalog.read_at(repo, commit)` reads the two catalog files in
`read`'s order through `parse`, labelling the catalog by its path in the
repository (`Catalog.file`, and the `CatalogError` prefix);
`catalog.files_at(repo, commit, directory)` is `files` at a commit for
`version`. In `outdated._compare`, a `behind` source with `plugins != ()`
reads both ends (`_end`), selects the names (either end under `"*"`, else
the listed names at either end), and reports each `ChangedPlugin(name,
change, version)`: *added*/*removed* by catalog, *modified* when the name's
entries (all of them, compared as canonical JSON) differ or a file under its
`InSource` directory at either end changed (`git diff --no-renames
--name-only`, the whole tree). `version` is a `Versions` TypedDict
`{"from", "to"}` taken as `status` takes it, from git at each end. A broken
catalog at either end sets `plugins_error` ("plugins not compared: the
catalog at the <pin|tip> (<sha12>) is broken: <path>: <error>") and leaves
`plugins` empty; the skills are unchanged. `SourceReport` gains `plugins`
and `plugins_error` after `skills`. `cli._outdated_text` takes the names of
sources that select plugins (from the manifest), prints
`plugins <change>: name (versions)` lines after the skills' lines, the
error line, and "no selected skill or plugin changed" for such a source.

**c — commits, `--diff`, `update`.** `Commit` gains `plugins`. When a
source's plugins were compared, `_Tracked.commits` runs one
`git log --no-renames --format=%H %P %s --name-only pin..tip` over the
whole tree and lists every commit touching selected skills (taken from the
existing skills log, by commit) or selected plugins: a file under a
plugin's directory at either end, or a catalog file changed so that the
plugin's entries differ from the first parent's (`_at`, cached per commit,
an unreadable catalog having none). A merge touches nothing. Otherwise the
commits are exactly the skills log's, with `plugins` empty. `--diff`
appends, per changed plugin in name order, `git --literal-pathspecs diff`
under its directories, then the entry's `difflib.unified_diff` (two-space
JSON in the catalog's key order; a name listed twice is the list of its
entries) headed `a/<catalog>#<name>`/`b/<catalog>#<name>` or `/dev/null`.
`update` is unchanged; README, the skill, and `outdated`'s `--help` text
describe plugins, and "upstream reports still track skills" is gone.

Deviation: the brief's Done-when for a says `test_state_findings_agree_with_status`
passes unchanged; it can't (see *Doc inconsistencies*), so it now skips
findings with no harness. `test_a_removed_cli_only_a_plugin_tack_cant_deploy_targets`
was also updated: its case is one the brief adds a finding for.

### Findings

1. **The brief's Done-when for unit a contradicted its own Build.** It kept
   `test_state_findings_agree_with_status` unchanged, but that test's
   `unreadable` fixture is exactly the plugin unit a gives a source
   finding (no harness), which its `_covered` couldn't place. The executor
   implemented the design and made the test skip harness-less findings,
   which keeps its intent; accepted. Severity: note (the brief's error,
   not the code's). Added as `brief-checklist §7`; the sweep of this
   brief's other "unchanged" claims (`test_leftovers_agree_with_sync`, the
   existing `outdated`, `cli`, TUI and examples tests) found none whose
   fixtures the units changed.
2. **Commit attribution misses file names git quotes.**
   `outdated._Tracked.commits` (new) parses `git log --name-only` without
   `-z`; git C-quotes a path holding `"`, `\`, a tab, a newline or another
   control character even with `core.quotePath=false`, so a commit whose
   only change under plugin `a` is to `plugins/a/x"y.md` lists nothing
   (probed), though `a` reads *modified* (that diff uses `-z`). The skills
   log in `_compare` and `sources.unpushed` have the same parse
   (pre-existing). Severity: follow-up. Filed as #47, scheduled as
   P0001-C08-a with #46; added as `review-checklist §2`.
3. **Units b and c landed before their CI ran.** Pushes failed with HTTP
   500 for about ten minutes after b's commit; b, c and the report then
   went up within two minutes, and the runs for `9fc884d` and `4b3eaab`
   are still `queued`. Nothing went red: each commit carries its gate
   line, and the run on the head (green) covers the same code, the report
   touching only the chunk file and the status file. Severity: note.
4. **A catalog symlinked out of the repository.** `catalog.read_at` calls
   it broken ("a link out of the repository"), while `catalog.read` on a
   checkout follows it. git can't read outside the repository, so that is
   the only reading available; design.md now says so. Severity: note;
   doc fixed in this review.
5. **Two wording choices the report raised.** With `plugins_error` set and
   no skill changed, the text says "no selected skill changed" (plugins
   weren't compared); design.md now says so. "tack can't manage
   <harness>'s plugins" for a harness finding naming no plugin fits *`doctor`
   checks* as written ("says only what is wrong with the harness"); no
   change. Severity: note.
