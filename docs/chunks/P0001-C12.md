# Chunk P0001-C12 — a plugin's repository, shown and diffed

**Goal:** a plugin from another repository says where it comes from and
what an `update` would take from it. `status --json` gives its
`repository` (URL, path, commit, clone and the clone's state), the TUI's
plugin detail shows the same in two lines, and `outdated --diff` follows
its entry's diff with the diff between its two commits, fetched into its
clone. This is the rest of D8: C11 wired the clones into `sync`, and these
are the two places a user still can't see them.

## Kickoff notes

`--diff` bullet and DEC-23, pinned at this cut. `outdated` fetches into a
clone but never creates, checks out or moves one, so a clone that isn't
there gives a line saying why, not a clone. Which plugins get a commit diff

## Units

### P0001-C12-a — `status --json` and the TUI name a plugin's repository

**Build** (design.md *Plugin states*, *The Plugins tab*):

- `plugins.Selected` carries the clone's state as `_files` read it (None
  without a clone), so nothing reads it again for `status`.
- `status.PluginStatus` gains `repository`: None for a plugin in its source
  or one tack can't deploy; for one from another repository, an object
  with `url`, `path` (None for the whole repository), `commit` (forty
  digits), `clone` (the clone's path) and `state` (the clone's state), in
  that order, after `path`. `status --json` prints it as design.md says.
  `status`'s text output is unchanged.
- The Plugins tab's detail, after the `source:` line, gives for such a
  plugin `repository: <url> at <commit[:12]>` (`<url> (<path>)` for a
  `git-subdir`) and `clone: <tilde(clone)> (<state>)`; nothing new for any
  other plugin.
- README (the `tack status --json` paragraph under *Plugins*) and
  `skills/tack/SKILL.md` (`status`'s plugin object) name `repository`.

**Tests:**

- `tests/test_status.py`: a `url` entry not cloned, then after `sync`
  (`ok`), then with the entry moved to the newer commit (`off its commit`,
  `commit` the newer one), then with local changes: `repository` each
  time; a `git-subdir` entry's `path`; a plugin in its source and one tack
  can't deploy have `repository` null. brief-checklist §7:
  `test_status_json_gives_plugins` asserts whole plugin objects, so each
  gains `"repository": None`.
- `tests/test_tui.py`: the detail of a plugin from another repository
  (whole and `git-subdir`) has the two lines with its URL, commit, clone
  and state; a plugin in its source has neither.
- A test that the plan reads a clone's state once per plugin for a
  `status` run (count `git status` calls, or patch `Clone.state`).

**Done when:** those pass; every other existing test passes unchanged; the
README and the skill describe `repository`.

### P0001-C12-b — `outdated --diff` between a plugin's commits (DEC-23)

**Build** (design.md *Tracking plugins upstream*, the `--diff` bullet;
DEC-23):

- For each changed plugin `--diff` covers, when it is *modified* and from
  another repository at both ends, with the same URL and a different
  commit: after its entry's diff, the diff between its two commits in its
  clone (`plugins/<source>/<name>/`), as design.md says: each commit the
  clone lacks fetched as `sync` fetches it (branches and tags, then by id),
  limited to the entry's `path` at each end (no pathspec when either end
  has none), file names headed `a/<name>@<pin's commit[:12]>/` and
  `b/<name>@<tip's commit[:12]>/`.
- In place of that diff, the line `plugin '<name>': no diff between its
  commits: <why>\n` when the clone isn't there (`it isn't cloned; `tack
  sync` clones it`), isn't a git checkout (`sync`'s message for a clone in
  the way), or the fetch fails or doesn't bring a commit (`sync`'s
  message: `can't fetch <url>: …`, `pinned commit <c[:12]> isn't in <url>`).
- `outdated` never creates, checks out or moves a clone: its `HEAD` and
  work tree are as they were, whatever its state; a clone with local
  changes or off its commit is fetched into all the same. Without
  `--diff`, nothing is fetched into any clone.
- README (`outdated`'s `--diff` under *Plugins*) and `skills/tack/SKILL.md`
  (`--diff`'s sentence) say a plugin from another repository also gets the
  diff between its commits, and that `outdated` never clones one.

**Tests** (`tests/test_outdated.py`; a git source whose catalog's entry for
`r` is an `elsewhere` remote's older commit, then a commit moving it to the
newer one; `sync` first, so the clone exists, unless the case says not):

- `url` entry: the diff has the entry's diff, then the commit diff with
  `diff --git a/r@<older12>/README.md b/r@<newer12>/README.md`, in that
  order; `git-subdir`: only files under its `path` (no `OTHER.md`).
- The newer commit made after the clone (so the clone lacks it): fetched,
  the diff given; the clone's `HEAD`, work tree and state unchanged. With
  local changes: fetched and diffed, the edit still there.
- The clone deleted after `sync` (without one, the source isn't checked
  out and `outdated` compares nothing): the reason line, and no clone
  directory made. Something in its place that isn't a checkout: `sync`'s
  message. The remote deleted and the clone
  lacking the newer commit: the fetch's failure as `sync` words it
  (review-checklist §1: delete the remote before the run).
- No commit diff, and no fetch, for: an entry whose URL changed, a plugin
  added or removed, one in the source at either end, and any run without
  `--diff` (the remote deleted, the clone's objects unchanged).
- The text and `--json` both carry it (`diff`); the existing `--diff`
  tests pass unchanged.

**Done when:** those pass; every other existing `outdated`, TUI and CLI
test passes unchanged; the README and the skill describe it.

## Notes for the executor

- Pull request title: `feat: show and diff plugins from other repositories
  (P0001-C12)` or similar.
- `sources._fetch(d, url, commit, by_id=True)` is the fetch `sync` uses; a
  small public wrapper (and one for the "in the way" message `_refuse`
  gives) keeps `outdated` from reaching into private names. `_Tracked`
  needs the source's name and `Paths` to find the clone.
- The `in the way` and `not cloned` checks need no `git status`: `.git`
  missing is enough to give the line, so `outdated` reads no clone's state.
- `git diff --src-prefix=… --dst-prefix=…` sets the headers;
  `--literal-pathspecs` as the plugin directory diff uses.
