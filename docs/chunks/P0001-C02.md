# Chunk P0001-C02 — Selecting plugins

**Goal:** what the manifest's `plugins` field will mean, built and tested
but not yet accepted. A parser in `config.py` reads the field's value into
`Source.plugins` and enforces its rules. `plugins.plan` turns a `Config`
into which plugin each harness should get from which source, alongside
the plugins a source lists but its catalog lacks, the ones it selects that
can't be deployed, and the names two sources both select. This completes
D1's code except for accepting the field. The chunk that makes `sync` deploy
will add the key and call both pieces. The chunk also makes the Codex
stand-in stricter (C01 review, finding 1). Nothing user-visible changes:
`plugins` stays an unknown key (P0001 §5).

### P0001-C02-b — The `plugins` field's parser, not yet wired in

**Build:** in `src/tack/config.py` (§5 *Source fields*; §9 *Selecting
plugins*; DEC-3, DEC-8, DEC-10):

- `Source.plugins`, in the same shape as `skills`: `None` for `"*"`, else a
  tuple of specs with a name and optional harnesses. Its default is `()`,
  meaning none (DEC-3), where `skills` defaults to `None`.
- A function that parses the field's value for a source, given the source's
  harnesses and the manifest's harnesses. It shares `_skills`' parsing
  rather than copying it: `"*"` or a list, names or `{ name, harnesses }`
  tables, no unknown table keys, valid names, no name twice, a plugin's
  harnesses within the source's. Messages name plugins where they name
  skills. The plugin-only rules come on top:
  - A plugin's `harnesses` may name only the built-in harnesses (DEC-8).
  - A source that selects plugins (`"*"` or a non-empty list) must target
    one of them (DEC-10). A source with no `harnesses` targets every
    harness, built-ins included, so it always passes. `[]` passes anywhere.
- The harnesses that take plugins are the built-in ones (DEC-8). `config`
  keeps that list, and `agents.CLIS` must agree with it; a test holds the
  two together.
- Nothing calls the parser yet. `_SOURCE_KEYS` doesn't change, so
  `plugins` is still an unknown key, and `config.parse` behaves exactly as
  before.

**Tests:** in `tests/test_config.py`, calling the parser directly:

- `"*"` gives `None`; `[]` gives `()`; names; a table with `harnesses`.
- Errors: a value that is neither `"*"` nor a list; an entry that is
  neither a string nor a table; a table with no `name`, or with an unknown
  key; an invalid name; a name listed twice; an unknown harness; a
  manifest-defined harness in a plugin's `harnesses` (DEC-8); a built-in
  harness outside the source's.
- DEC-10: a source whose `harnesses` are only a manifest-defined harness
  fails with `"*"` and with `["x"]`, and passes with `[]`. A source
  targeting that harness and `codex` passes.
- `Source(...).plugins` defaults to `()`.
- A manifest whose source sets `plugins` still fails as an unknown key.
- The built-in harness list and `agents.CLIS`' keys are the same set.

**Done when:** those pass, and every existing `skills` test passes
unchanged.

### P0001-C02-c — The plan

**Build:** `plugins.plan(cfg)` in `src/tack/plugins.py` (§9 *Selecting
plugins*, both paragraphs after the example; §9 *Catalogs*; DEC-3, DEC-4,
DEC-8, DEC-10). It is shaped like `deploy.plan`:

- **Per source that selects plugins.** A source with `plugins == ()`
  doesn't appear, and its catalog isn't read. For each source that does
  appear, the plan holds:
  - its catalog's state: found, no catalog file, root not there, or
    broken with `CatalogError`'s message;
  - the plugins it selects. `"*"` selects every plugin in the catalog, in
    catalog order. A list selects each listed name the catalog has,
    deployable or not;
  - the listed names its catalog lacks;
  - the catalog's ignored entries, as `catalog.read` gives them, for a
    caller to report.

  With no catalog file, it selects nothing and lacks every listed name.
  With no root, or a broken catalog, it selects nothing and lacks nothing.
- **Each selected plugin** carries its source, its `catalog.Plugin`, and
  the harnesses it targets: its own `harnesses` if given, else the
  source's, else every harness, keeping only the built-ins (DEC-8). An
  `InSource` plugin also carries its directory: the source root (as
  `sources.root` gives it) joined with the path, or the root itself for
  `"."`. Other plugins have no directory; D8 supplies one for `InRepository`
  plugins.
- **Per harness that takes plugins.** Each name maps to the one selected,
  deployable (`InSource` or `InRepository`) plugin for it. Collided names
  and undeployable plugins are left out.
- **Collisions.** Each name that two or more sources select for the same
  harness maps to its harnesses and sources, as in `deploy.Plan`. A
  plugin counts whether or not it is deployable.

**Tests:** in a new `tests/test_plugin_plan.py`, with `path` sources and
catalogs written under the temporary directory:

- `"*"` selects every plugin in catalog order. A list selects only the
  named ones, and a listed name the catalog lacks is in the source's
  missing names.
- Per-plugin `harnesses`. A source limited to `codex`. A source targeting a
  manifest-defined harness and `codex`, whose plugins go to `codex` only.
- Directories for `"./plugins/x"`, `"."`, and a bare name under
  `metadata.pluginRoot`. An `InRepository` plugin has none, but is in its
  harnesses' plugins.
- An `npm` plugin, and a name listed twice in a catalog: both selected and
  undeployable, and in no harness's plugins.
- Collisions: two sources selecting `x` for the same harness, in neither
  source's harness map; per-plugin harnesses that don't overlap, with no
  collision; an undeployable `x` colliding with a deployable `x`.
- Catalog states: no catalog file (with `"*"`, and with a list); a `path`
  source whose directory is missing; a broken catalog, with its message.
  Each selects and lacks what *Selecting plugins* says.
- A source with `plugins = ()` beside a broken catalog isn't in the plan,
  so the catalog was never read (`review-checklist §1`). A plan over
  several sources leaves the stand-ins' call log empty and creates no
  `<data>/marketplace`.

**Done when:** those pass, and `deploy.plan`, `sync` and `config.parse`
are unchanged.
