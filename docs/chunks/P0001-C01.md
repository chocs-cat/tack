# Chunk P0001-C01 — Catalogs, tack's marketplace, and the agents' CLIs

**Goal:** the three building blocks `sync` will drive, each tested on its own
and none of them wired in yet. `catalog.py` reads a source's catalog in either
agent's format and says, for each entry, where the plugin is or why tack can't
deploy it. `plugins.py` keeps tack's marketplace: copies of plugins, their
hashes, and tack's catalog. `agents.py` runs `claude plugin` and
`codex plugin` and reads their answers, and every test gets stand-in CLIs in
place of the real agents. They come first because both halves of the project's
D1 and D2 rest on them, and each can be pinned by tests without a manifest
field. Nothing user-visible changes: the manifest still rejects `plugins` as
an unknown key, because no chunk may accept that field before `sync` deploys
it (P0001 §5). Issue [#22](https://github.com/chocs-cat/tack/issues/22) stays
open; the project closes it.

## Units

### P0001-C01-a — Read catalogs

**Build:** `src/tack/catalog.py` (§9 *Catalogs*; DEC-4):

- `find(root)`: the catalog file of a source rooted at `root`,
  `.claude-plugin/marketplace.json`, else `.agents/plugins/marketplace.json`,
  else none. Precedence is by existence: a broken `.claude-plugin/` catalog is
  not passed over for the other.
- `parse(data, file)`: pure (no filesystem); takes the decoded JSON, of any
  type, and a label for messages. It raises `CatalogError` when `data` isn't
  an object with a `plugins` list. Otherwise each entry becomes exactly one
  of: **in the source** (its directory as a normalized POSIX path relative to
  the source root, `"."` for the root); **in another repository** (clone URL,
  path inside it or none, commit); or **not deployable** (a reason naming what
  is wrong: the type, the missing `sha`, the `..`, the bare name with no
  `metadata.pluginRoot`, the missing field). Every plugin keeps its upstream
  entry object, which tack's catalog copies. Ignored entries (not an object,
  or no `name` valid by `config.valid_name`) are kept with their index and
  why, for a caller to report; a name listed twice makes each of its entries
  not deployable.
- `read(root)`: `find`, decode UTF-8 JSON, `parse`; none when there is no
  catalog, and `CatalogError` for a file it can't read or decode.
- `version(…)`: §9 *Catalogs*' last paragraph (`.claude-plugin/plugin.json`,
  `plugin.json`, `.codex-plugin/plugin.json`, each skipped if unreadable,
  malformed or without a string `version`; then the entry's; then none).
  Keep the precedence in one function, shaped so a later chunk can feed it
  file contents read from git at a commit rather than from a directory.

**Tests:** `tests/test_catalog.py`:

- `find`: only `.claude-plugin/`, only `.agents/plugins/`, both (the
  `.claude-plugin/` one), neither; `read` of a broken `.claude-plugin/`
  catalog beside a good `.agents/plugins/` one raises `CatalogError`.
- `parse`, one case per kind: `"./plugins/x"`, `"./"`, `"."`, a trailing
  slash; a bare name under `metadata.pluginRoot` set to `"./plugins"` and to
  `"plugins"`; a bare name with no `pluginRoot`, and with a `pluginRoot` that
  leaves the source; `"plugins/x"` (no `./`); an absolute path; a `..` path,
  including one that would land back inside; Codex
  `{"source": "local", "path": "./plugins/x"}`; `url`; `github` (the URL built
  from `repo`); `git-subdir` with a full URL and with `owner/repo` shorthand,
  with a `./`-prefixed `path` and with a `..` one; each git type with a full
  `sha`, with only a `ref`, with an uppercase `sha` and with a short one;
  `npm`, `archive`, `command`, an unknown type, a `github` without `repo`.
- `parse`: an entry that isn't an object and one with an invalid name are
  ignored and listed; a duplicate name; `CatalogError` for a list, a string,
  and an object without `plugins`; the upstream entry kept unchanged.
- `version`: each `plugin.json` location winning over the ones after it and
  over the entry; a malformed one skipped; the entry alone; none.

**Done when:** every case above passes, and the `parse` tests run on plain
dicts with no directory behind them.

### P0001-C01-b — tack's marketplace

**Build:** in `src/tack/plugins.py` (§9 *Deploying*, its two bullets and the
first sentence after them; §9 *Plugin ownership*, the hash paragraph; DEC-1,
DEC-2, DEC-6), and `Paths.marketplace_dir`, `<data>/marketplace` (§4 *Files
and locations*):

- `tree_hash(directory)`: exactly the hash §9 *Plugin ownership* defines. A
  dangling symlink or a loop is an error its caller reports.
- Bringing the marketplace up to date for the wanted plugins (each a name,
  its directory, and its upstream entry): copy each plugin that has no copy
  or whose copy's hash differs from its directory's. Build the copy under a
  dot-named temporary directory in `plugins/` and swap it in. A missing
  directory, a dangling symlink, a loop or an `OSError` fails only that
  plugin, with a message, and leaves any copy it had. Then write
  `.claude-plugin/marketplace.json` as §9 *Deploying* specifies, one entry
  for each wanted plugin that has a copy, sorted by name, through
  `config.write_atomic`, and only when its content changes. Each copy is a
  change `copy` and a rewritten catalog a change `write` (the actions §9
  names; `write` as for the lockfile). A dry run reports the same and writes
  nothing.
- The plugins that have a copy; dropping one copy; removing the whole
  directory. `sync` will drop a deselected plugin's copy only after
  uninstalling it, so updating the marketplace never deletes a copy itself.

**Tests:** `tests/test_marketplace.py`:

- A first update copies every plugin and writes the catalog: assert its
  exact JSON (`name`, `owner`, entries by name, `source` replaced, `headers`
  and `headersHelper` gone, every other upstream field kept).
- A second update changes nothing (no change, no file rewritten); an edited
  file brings one `copy`; an entry-only change brings a `write` and no copy.
- `.git` left out, as a directory at the top and as a file deeper down; a
  symlinked file and a symlinked directory copied as real ones.
- A dangling symlink, a loop, and a missing directory each fail only their
  plugin, keep its earlier copy, and let the others copy.
- Dropping a copy, removing the directory, and a dry run that writes nothing.
- `tree_hash`: a plugin with a symlink and a `.git` hashes the same as its
  copy; the hash changes with a file's contents, its executable bit, and a
  renamed file, and not with an empty directory.

**Done when:** those pass and nothing outside `<data>/marketplace` is
written.

Stand-ins (§17 *Implementation*):

- An autouse fixture in `tests/conftest.py`, beside `home`: writes `claude`

  other `PATH` directory holding a `claude` or `codex`, and links `git` into
  the bin directory if dropping a directory took it away.
- Behavior, per §16: the list shapes; registering twice; installing an
  installed plugin; installing a plugin the registered directory's
  `.claude-plugin/marketplace.json` lacks fails (`not_found`, or `Error:` for
  Codex); Claude Code's `uninstall` of a plugin that isn't installed fails
  (`not_installed`); `codex plugin remove` always succeeds; Claude Code's

- Helpers for tests: seed state (a foreign marketplace named `tack`, a

**Tests:** `tests/test_agents.py`:

### What landed

**a: reading catalogs.** `src/tack/catalog.py`: `find(root)` picks
`.claude-plugin/marketplace.json`, else `.agents/plugins/marketplace.json`, by
existence (a dangling symlink counts), so a broken Claude Code catalog is
never passed over. `read(root)` decodes UTF-8 JSON and raises `CatalogError`
naming the file. `parse(data, file)` is pure and returns a `Catalog` of
`Plugin(name, where, entry)`, where `where` is `InSource(path)` (a
normalized POSIX path, `"."` for the root), `InRepository(url, path,
commit)` or `Undeployable(reason)`, plus `Ignored(index, reason)` entries,
indexed from 0. A name listed twice makes each of its entries undeployable,
and both stay in the list. A `pluginRoot` that is unusable (absolute, with a
`..`, empty, or not a string) is named in the reason a bare name gets.
`version(entry, read)` keeps the `plugin.json` precedence over a file
reader; `files(directory)` is the reader for a directory, and a later chunk
can pass one over git at a commit.

**b: tack's marketplace.** `Paths.marketplace_dir` (`<data>/marketplace`),
and `src/tack/plugins.py`:
- `tree_hash(directory)` is the §9 hash: per file, its path, an executable
  flag and the SHA-256 of its contents, NUL-separated, in path order.
- `update(paths, wanted, dry_run=)` copies stale or missing plugins and
  rewrites `.claude-plugin/marketplace.json` only when its text changes. It
  returns `Update(changes, failures)`, with its own `Change` (`copy` or
  `write`) and `Failure`, so it doesn't import `sync`; the later chunk that
  wires it into `sync` will map them.
- A copy is built in `plugins/.<name>.XXXX` and swapped in by renaming the
  old copy aside and then deleting it.
- `copies`, `drop` and `remove`.

One thing the brief didn't ask for: `update` (when not a dry run) deletes
dot-named directories that an interrupted copy left in `plugins/`. Plugin
names can't start with a dot, so these are never copies.

**c: the agents' CLIs and stand-ins.**
- `src/tack/agents.py`:
  - `CLIS` and `available(harness)`.
  - Command builders that return a `Command(harness, kind, args)`: `list_plugins`, `list_marketplaces`, `register`, `install` (which also reinstalls in Codex), `uninstall` and `unregister`. `str()` of a command is its shell-quoted line.
  - `run(command, paths) -> Outcome(command, output, error, missing)`.
  - `inventory(harness, paths) -> Inventory | Outcome`, which holds `Installed(name, marketplace, enabled, scope)` and `Marketplace(name, kind, location)`.
  - `is_tack(harness, marketplace, paths)`.
- `tests/standin.py` is the stand-in script. It is stdlib-only and runs outside pytest (`python tests/standin.py bin <dir>`, with `STANDIN_AGENTS_DIR` set). It also holds the `Standins` helpers: `marketplace`, `plugin`, `answer`, `fail`, `remove`, `calls` and `state`.
- The autouse `standins` fixture in `tests/conftest.py`.

**Deviation from the brief:** the brief had the fixture drop each `PATH`
directory holding an agent and link `git` back. That broke the formula test
