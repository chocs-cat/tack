# Chunk P0001-C06 — `doctor` audits plugins

**Goal:** `tack doctor` reports plugins: a selected plugin that isn't
`installed` where it should be, a source whose catalog doesn't give what
the manifest asks, tack's plugins that `sync` would uninstall, two sources
selecting one name, plugins someone else installed (`unmanaged-plugin`),
and plugins an agent loads twice (`duplicate-plugin`), with the
`ignore_marketplaces` harness field quieting the agents' own. D4 comes
after D3 because `not-synced` reads the states `status` now gives. Unit a
is the C05 review's follow-up: a `path` source whose root is gone says so
(#40).

### P0001-C06-b — The `ignore_marketplaces` harness field

**Build** (design.md *Harness fields*; DEC-8):

- `config`: `ignore_marketplaces`, a list of strings, accepted in the
  `[harness.claude-code]` and `[harness.codex]` tables and added to the
  built-in lists in the *Harness fields* table; `Harness` carries the
  result (empty for a manifest-defined harness). In a manifest-defined
  harness's table it is a configuration error saying only the built-in
  harnesses take plugins.
- The TUI's Settings *Harnesses* note says `ignore_marketplaces` is edited
  in `tack.toml` by hand (design.md *The TUI*, *Settings*).
- `skills/tack/SKILL.md` (beside `[harness.<name>] ignore`) and `README.md`
  describe the field (review extras).

**Tests:** in `tests/test_config.py`: the built-in lists with no table;
a listed name added to them, not replacing them, for each built-in; the
field in a manifest-defined harness and a value that isn't a list of
strings each a `ConfigError` naming the table.

**Done when:** those pass, and a manifest without the field loads exactly
as before.

### P0001-C06-c — Plugin `not-synced` and `name-collision`

**Build** (design.md *`doctor` checks*, the *(P0001)* paragraph's first
four bullets; DEC-5, DEC-7, DEC-11, DEC-15 – DEC-18):

- `doctor/plugins.py`, whose `check(cfg)` `doctor.run` calls with the
  global checks, right after `skills.check`. It reads each built-in
  harness's inventory (`agents.inventory`) once per run, whatever the
  manifest selects (DEC-18); `--projects-only` runs no agent.
- A selected plugin's state in each harness comes from the one function
  `status` uses, given the inventories `doctor` read, so no `list` runs
  twice in a `doctor` run and `status`'s behavior doesn't change.
- `not-synced` (warn) as the bullets say: per plugin and harness for
  `missing`, `disabled` and `stale`, at the plugin's directory in its
  source; per harness for `unavailable` (with the agent's message: the
  inventory's `Outcome.error`) and for `conflict` (with the foreign
  marketplace's location), naming the plugins they stop, with no path. For
  a source, at its catalog file (`catalog.find`) or its root when it has
  none: each listed name the catalog lacks, each selected plugin tack can't
  deploy (with the reason), a broken catalog (with its error); and until D8
  a selected plugin from another repository, reported as `sync` reports it.
  Such plugins, and collided names, get no per-harness finding.
- Leftovers: `not-synced` per harness for each of tack's plugins there
  that step 4 would uninstall: its candidates (Claude Code: the user-scope
  plugins it lists from tack's marketplace; Codex: those and the record's),
  less the plugins the manifest deploys there and the kept ones the bullet
  names. None in a harness with a foreign `tack`. No path.
- `name-collision` (error) once per collided plugin name, at the manifest,
  naming the sources and harnesses as `sync`'s `collision` problem does.
- Order: the plugin `name-collision`s by name; each source's findings in
  manifest order; then per harness (`claude-code`, then `codex`): its
  `unavailable` or `conflict`, the per-plugin states by name and source,
  then the leftovers by name. Every finding about a harness carries it in
  `harness` and names the agent in its message (the text output shows only
  a path), and says what fixes it: `tack sync`, turning the plugin on in
  the agent or limiting its `harnesses` for `disabled` (DEC-5), installing
  the CLI, or removing or renaming the foreign marketplace.

**Tests**, in a new `tests/test_doctor_plugins.py` against the stand-ins:

- Agreement with `status`: for each fixture in `test_status.FIXTURES`, the
  per-plugin and per-harness `not-synced` findings cover exactly the
  (plugin, harness) cells `status` gives a state other than `installed` and
  `collision`, with that state's finding.
- Agreement with `sync`: for each of: a plugin deselected after a sync, one
  narrowed to `harnesses = ["codex"]` after a sync, a `name@tack` installed
  by hand in Claude Code, a deselected plugin the record lists in Codex
  that Codex's list hides (its entry taken out of tack's catalog by hand),
  a collided name, a recorded plugin whose `path` source's
  root is gone, and one whose catalog has broken, the leftovers per harness
  equal a `sync.sync(cfg, dry_run=True)`'s `uninstall` changes there.
- Each source finding and `name-collision`, with its severity and path; a
  plugin tack can't deploy reported once; a disabled plugin's message names
  turning it on and `harnesses`; `unavailable` from a failing `plugin list`
  carries the agent's message.
- Calls: plugins selected for both harnesses runs exactly the four `list`
  commands; no plugins selected and a plugin installed by hand still runs
  them (DEC-18); a removed CLI runs nothing there and yields no finding
  unless a selected plugin targets it, then one `unavailable`;
  `doctor.run(cfg, global_checks=False)` with plugins selected and one
  installed by hand runs none.

**Done when:** those pass, `tack doctor --json` lists these findings in the
existing finding shape, and every existing `doctor`, `cli` and TUI test
passes unchanged.

### P0001-C06-d — `unmanaged-plugin` and `duplicate-plugin`, and the docs

**Build** (design.md *`doctor` checks*, the last bullet and the paragraph
after it; *Harness fields*):

- `unmanaged-plugin` (info) per plugin a harness has from a marketplace
  that isn't tack's (a foreign `tack` included), at user scope in Claude
  Code, whose marketplace isn't in the harness's `ignore_marketplaces`;
  named by its id.
- `duplicate-plugin` (warn) per plugin the manifest deploys to a harness
  (in `plugins.plan`'s plugins for it) that the harness also has from
  another marketplace (user scope in Claude Code), whatever
  `ignore_marketplaces` says, naming both ids; such a plugin isn't also
  `unmanaged-plugin`. None in a harness with a foreign `tack`.
- Both per harness after unit c's findings for it: `duplicate-plugin` by
  name, then `unmanaged-plugin` by id. No path.
- `README.md` and `skills/tack/SKILL.md` (review extras): what `doctor`
  reports about plugins, a line per case, that it lists every installed
  agent's plugins (DEC-18), and "… don't show plugins yet" naming only the
  TUI.

**Tests:** a hand-installed plugin is `unmanaged-plugin` with no plugin
selected; the built-in ignored marketplaces (one for each agent) and a
listed one aren't reported; a Claude Code install at `project` scope and a
`synced` one aren't; a plugin from a foreign `tack` is; a selected plugin
also installed from another marketplace is `duplicate-plugin` and not
`unmanaged-plugin`, also when that marketplace is ignored; none in a
harness with a foreign `tack`. Through `cli.main(["doctor", "--json"])`:
`unmanaged-plugin` alone exits `0`, a `duplicate-plugin` exits `1`.

**Done when:** those pass, and neither the README nor the skill says
`doctor` doesn't show plugins.
