# Chunk P0001-C06 — `doctor` audits plugins

**Goal:** `tack doctor` reports plugins: a selected plugin that isn't
`installed` where it should be, a source whose catalog doesn't give what
the manifest asks, tack's plugins that `sync` would uninstall, two sources
selecting one name, plugins someone else installed (`unmanaged-plugin`),
and plugins an agent loads twice (`duplicate-plugin`), with the
`ignore_marketplaces` harness field quieting the agents' own. D4 comes
after D3 because `not-synced` reads the states `status` now gives. Unit a
is the C05 review's follow-up: a `path` source whose root is gone says so
(#40).

### P0001-C06-c — Plugin `not-synced` and `name-collision`

  manifest selects (DEC-18); `--projects-only` runs no agent.
- A selected plugin's state in each harness comes from the one function
  `status` uses, given the inventories `doctor` read, so no `list` runs
  twice in a `doctor` run and `status`'s behavior doesn't change.
- `not-synced` (warn) as the bullets say: per plugin and harness for
  `missing`, `disabled` and `stale`, at the plugin's directory in its
  source; per harness for `unavailable` (with the agent's message: the
  inventory's `Outcome.error`) and for `conflict` (with the foreign
  marketplace's location), naming the plugins they stop, with no path. For
  a source, at its catalog file (`catalog.find`) or its root when it has
  none: each listed name the catalog lacks, each selected plugin tack can't
  deploy (with the reason), a broken catalog (with its error); and until D8
  a selected plugin from another repository, reported as `sync` reports it.
  Such plugins, and collided names, get no per-harness finding.
- Leftovers: `not-synced` per harness for each of tack's plugins there
  that step 4 would uninstall: its candidates (Claude Code: the user-scope
  plugins it lists from tack's marketplace; Codex: those and the record's),
  less the plugins the manifest deploys there and the kept ones the bullet
  names. None in a harness with a foreign `tack`. No path.
- `name-collision` (error) once per collided plugin name, at the manifest,
  naming the sources and harnesses as `sync`'s `collision` problem does.
- Order: the plugin `name-collision`s by name; each source's findings in
  manifest order; then per harness (`claude-code`, then `codex`): its
  `unavailable` or `conflict`, the per-plugin states by name and source,
  then the leftovers by name. Every finding about a harness carries it in
  `harness` and names the agent in its message (the text output shows only
  a path), and says what fixes it: `tack sync`, turning the plugin on in
  the agent or limiting its `harnesses` for `disabled` (DEC-5), installing
  the CLI, or removing or renaming the foreign marketplace.

**Tests**, in a new `tests/test_doctor_plugins.py` against the stand-ins:

- Agreement with `status`: for each fixture in `test_status.FIXTURES`, the
  per-plugin and per-harness `not-synced` findings cover exactly the

- Agreement with `sync`: for each of: a plugin deselected after a sync, one

- Each source finding and `name-collision`, with its severity and path; a
  plugin tack can't deploy reported once; a disabled plugin's message names

- Calls: plugins selected for both harnesses runs exactly the four `list`
