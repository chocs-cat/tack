## Units

### P0001-C04-a — tack's marketplace is up to date whenever it exists

**Build:** in `sync._Plugins.run` (§9 *Deploying*, "brought up to date
whenever a plugin is selected or the directory exists"): `plugins.update`
runs when any plan source selects a plugin or tack's marketplace directory
exists, in place of C03's "when something is wanted or kept". With nothing
selected and the directory there, it writes tack's catalog without the
deselected entries (a `write` change) before the harness steps. With
nothing selected and no directory it still doesn't run, so it never
creates the directory. Fixes #33.

**Tests:** in `tests/test_sync_plugins.py`:
`test_deselecting_the_last_plugin_unregisters_then_deletes_the_marketplace`
now expects that `write` first. Deselecting the last plugin when `codex
plugin marketplace remove` fails leaves the directory, and tack's catalog
then names exactly the copies still in it. The existing manifest-without-
plugins test still sees no call and no directory.

**Done when:** those pass; restoring the wanted-or-kept condition fails the
failed-unregister test.

### P0001-C04-b — A held source keeps its plugins

**Build:** in `sync._Plugins` (§9 *Deploying*, the sources that keep their
plugins; DEC-12 and its clarification):

- `sync` hands the plugin pass the sources `_sources` holds. A source
  *keeps its plugins* when `sync` holds it, or its plan state is `no-root`
  or `broken`.
- Every name such a source selects (its plan `selected`, deployable,
  collided or not) and every name the record lists from it, in any
  harness, joins the kept names before `plugins.update` runs. From there
  C03's handling applies unchanged: its copy and catalog entry stay, and
  no step installs, reinstalls or uninstalls it.
- A record entry from a source that is no longer in the manifest isn't
  kept: it is uninstalled as before (unit d's `remove`).
- No new problem: the hold or the broken catalog is already reported.

**Tests:** in `tests/test_sync_plugins.py`, each starting from plugins a
real sync installed in both harnesses and recorded from the source:

- A `path` source whose path is gone: no `install`, `reinstall` or
  `uninstall` command, the copy and catalog entry unchanged, the record
  unchanged. Claude Code stays registered (DEC-13); Codex, which nothing
  else targets, is unregistered and its plugin stays installed. Once the
  path is back, the next sync registers Codex again and runs no install or
  reinstall, and a plugin deselected meanwhile is uninstalled then.
- A broken catalog: the same keep, beside its `source` problem.
- A git source `sync` holds (a refused checkout or a failed fetch, as
  `test_sync.py`'s held-source tests make one): its plugins kept,
  including one it newly selects, which is neither copied nor installed.
- A dry run with a git source whose checkout is gone: no `uninstall` and no
  `delete` among the changes for its recorded plugins.

**Done when:** those pass; dropping either half of the kept names (the
record's, or the selected ones) fails a test.

### P0001-C04-c — `skills = []` needs no skills directory

**Build:** design.md *Source fields*: a source with `skills = []` is
present when its root is there, whether or not its skills directory is.
One rule, used by `deploy.plan`'s `SourceState.present`, `sync`'s hold of a
`path` source, `status`'s source state `missing`, and `doctor`'s
`not-synced` for a source. A `skills = []` `path` source whose path is gone
is still held, and `sync`'s problem says `no directory at <path>`; every
other source keeps its current wording.

**Tests:** in the sync, status and doctor test files: a `path` source with
`skills = []` and no skills directory gets no problem, no `missing` state
and no finding, and isn't held (a link it made under `skills = "*"` is
removed as deselected). With its path gone: held with `no directory at …`,
`missing`, and doctor's "has no directory at". A `skills = "*"` source with
no skills directory is still reported by all three.

**Done when:** those pass, and every existing test passes unchanged.

### P0001-C04-d — The manifest takes `plugins`

**Build:**

- `config`: `plugins` joins the source keys, and `_source` reads it with
  `parse_plugins` (*Source fields*, *Selecting plugins*; DEC-3, DEC-8,
  DEC-10). `parse_plugins`'s docstring loses "Nothing calls it yet".
- `tests/helpers.configure` builds its `Config` from a manifest that holds
  each selection, so every plugin test reads `plugins` as a user's
  manifest does; its docstring says so.
- design.md: the plugin-only source example moves from *Selecting plugins*
  into the manifest example under *The manifest*, and the sentence saying
  it would is removed.
- `remove` of a source whose plugins are installed uninstalls them through
  its sync (*Adding and removing sources*; D2). Nothing new to build, as
  far as the brief knows: prove it.
- `README.md` and `skills/tack/SKILL.md` (review extras): `plugins` and
  `skills = []` among the source fields, and what `sync` does with plugins:
  tack's own `tack` marketplace and `<name>@tack` installs, made through
  `claude` and `codex` (needed on `PATH` only when a selected plugin
  targets that agent), `agent` problems, a dry run listing the commands,
  and tack never enabling or disabling a plugin. Describe only what is
  built: `status`, `doctor` and the TUI don't show plugins yet.

**Tests:**

- `tests/test_config.py`: a manifest selecting plugins (`"*"`, a list, a
  table with `harnesses`) loads; a plugin `harnesses` naming another
  harness, a source selecting plugins that targets neither plugin harness,
  and a name listed twice each fail `config.load` naming the manifest; the
  "unknown key 'plugins'" test goes; `test_design_example_manifest_parses`
  asserts the new source's `skills == ()` and `plugins ==
  (SkillSpec("skill-creator"),)`.
- Through `cli.main` with a `tack.toml` holding a plugin source:
  `["sync", "--json"]` exits `0` and its changes include `register` and
  `install` with their harness and command line; `["sync", "--dry-run"]`
  prints `would run`; `["remove", "<source>"]` uninstalls in both
  harnesses, unregisters, deletes tack's marketplace directory, and leaves
  `state.json` without `plugins`.

**Done when:** those pass, the whole suite passes on `configure`'s new
footing, and the README and the agent skill describe the field.
