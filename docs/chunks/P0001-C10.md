# Chunk P0001-C10 — plugins' clones, and the C09 follow-ups

**Goal:** tack can keep a plugin's clone the way it keeps a git source's
checkout: clone it, bring it to the catalog's commit (fetching by id when no
branch or tag reaches it), refuse local changes, say what state it is in,
and `remove` deletes a source's clones. That is the groundwork of delivery
item D8 (plugins from other repositories); nothing deploys a clone yet, as
P0001-C01 built tack's marketplace before `sync` used it. The catalog fixes
D8 needs (#29) come with it, and unit a takes the P0001-C09 review's
follow-ups: git's background maintenance in the tests, #51, and a missing
Plugins-tab test.

## Kickoff notes

Unit c is the one to read slowly. design.md *Plugins from other
repositories* was pinned at this cut (DEC-21): a clone is kept "as a
checkout is, with the same code", so the work is to factor what
`sources.sync_git` does after pinning (clone, fetch, check out, refuse) into
one function both call, with source checkouts' behavior and messages
unchanged, not to write a second copy. Fetching by id is the one thing a
clone does that a checkout doesn't. In tests, a remote given as a plain
local path is cloned by copying every object, so a fetch-by-id test passes
whether or not the code fetches by id: use `file://` URLs, which unit b
makes the only local form a catalog `url` may take anyway. The reviewer
will run c's tests with the remote deleted where a test says nothing is
fetched.

### P0001-C10-c — a plugin's clone, kept as a checkout is

**Build** (design.md *Plugins from other repositories*, pinned at this cut;
DEC-21; *Files and locations*):

- Where a plugin's clone lives: `plugins/<source>/<plugin>/` under tack's
  data directory (`TACK_DATA` moves it). Its plugin directory: the clone, or
  the entry's `path` inside it.
- A clone's state, the first that applies: `in the way`, `not cloned`,
  `local changes`, `off its commit`, `ok`, as the section defines each.
- Bringing a clone to an `InRepository`'s commit, with the code that brings
  a source's checkout to its pin (factor it out of `sources.sync_git`; that
  function's behavior and messages don't change): clone when not cloned,
  fetch only when the clone lacks the commit (branches and tags, then, for
  a clone only, the commit by its id), check out detached; `origin`
  follows the URL. It gives the steps `clone` (the URL) and `checkout` (the
  commit's first twelve digits), and fails with what a checkout says in the
  same case (`in the way`, `local changes`, a clone or fetch that fails, a
  commit not in the repository), leaving an `in the way` or `local changes`
  clone untouched. A dry run clones and fetches nothing and gives the steps
  it would take.
- `remove` deletes the source's clones after its sync, each as it deletes
  the checkout (`edit._delete`: a `delete` change, or a problem and the
  clone left), then `plugins/<source>/` once empty; a name only the
  lockfile has too (*Adding and removing sources*, `remove`).
- Nothing else calls the clone code yet: the plan, `sync`, `status`,
  `doctor`, `add` and the TUI are unchanged (P0001-C11 wires them).

**Tests** (a new `tests/test_clones.py`, or beside `test_sources.py`;
remotes as `file://` URLs):

- Each state, from a clone made for it.
- Not cloned: cloned at the commit, steps `clone` then `checkout`, `HEAD`
  the commit. Off its commit, with the commit present: only `checkout`, and
  with the remote deleted first (review-checklist §1). Off its commit
  without it: fetched, checked out. `ok`: no steps, the remote deleted
  first.
- A commit only a ref outside `refs/heads` and `refs/tags` reaches (say
  `refs/pins/x`): fetched by id. A commit the remote doesn't have: fails,
  with the message a source's checkout gives for a pin it can't find, the
  same function producing both.
- Local changes and in the way: each fails with a checkout's message, and
  `tree()` of the clone is unchanged.
- `origin` follows: the URL changed to a second remote that has the
  commit, the clone fetches from it and its `origin` is the new URL.
- Dry run: from not cloned, steps `clone` and `checkout` and nothing
  written; from off its commit (lacking it), `checkout` and nothing fetched.
- The state and a dry run agree: for each state, `ok` gives no steps, `not
  cloned` gives `clone` and `checkout`, `off its commit` gives `checkout`,
  and the other two fail (brief-checklist §5).
- `remove` (in `tests/test_edit.py`): a source with two clones, one with
  local changes: the clean one deleted as a `delete` change, the other
  left and reported, `plugins/<source>/` kept while it holds it; a source
  whose clones are all clean loses `plugins/<source>/`; a dry run deletes
  nothing and lists the `delete`s; a lockfile-only name's clones go too.

**Done when:** those pass, and every existing `sources`, `sync`, `update`
and `remove` test passes unchanged (one implementation of a checkout).

### What landed

**a — the C09 review's follow-ups.** `tests/conftest.py`'s scratch git
config sets `maintenance.auto = false`, and the `GIT_CONFIG_*` override in
`test_a_git_dry_run_ignores_a_leftover_checkout` is gone (its now-unused
`monkeypatch` parameter with it). #51: `plugins.kept(plan, record, held=())`
is the one definition of the plugins `sync` keeps wherever they are
installed, short of those whose copy fails: a collided name, a plugin from
another repository, and each plugin a source selects or the record lists
from it when `sync` holds that source or can't read its catalog.
`doctor/plugins._kept` is gone; `doctor` calls `plugins.kept(plan,
record)`. `plugins.problems(sel, plan, kept)` reports no unreadable copy for
a kept name; `render.plugin_abouts(plan, kept)` passes it, and the TUI's
worker reads the record for it. *Deviation:* `sync._Plugins` built the same
set inline (with its held sources), so it now calls `plugins.kept(plan,
record, held)` too, the fix #51 proposed ("the TUI, `doctor` and `sync`
share one definition"); the brief named only `doctor` and `problems`.

**b — catalog URLs (#29).** `is_url` moved from `edit.py` to `git.py`,
which `edit` and `catalog` both import; `edit` imports the name, so
`edit.is_url` still answers. In `catalog._where`, a `url` source's `url`,
and a `git-subdir` `url` that isn't owner/repo, that `git.is_url` rejects
is `Undeployable("`url` '<url>' isn't a git URL")` (`… or owner/repo` for
`git-subdir`). A `git-subdir` `path` of `.` or `./` gives
`InRepository.path is None`.

**c — a plugin's clone.** In `sources.py` (where design.md *Implementation*
puts clones): `_refuse(d)` (in the way / local changes raise, the checkout
untouched; returns whether it is there) and `_bring(d, url, commit, there,
dry_run, by_id)` (clone when not there, fetch only when the commit is
missing, check out detached; a dry run clones and fetches nothing) are
what `sync_git` did after its pin, and `sync_git` now calls them around
the pin. `_fetch(checkout, url, commit, by_id)` makes `origin` follow the
URL and, `by_id`, runs `git fetch origin <sha>` when no branch or tag
reaches the commit; `fetch(checkout, source, commit)` keeps its signature
for `outdated`. `Clone(path, where)`: `Clone.of(paths, source, plugin,
where)` puts it at `Paths.clones_dir / source / plugin`
(`<data>/plugins/…`), `.directory` is the clone or `where.path` in it,
`.state()` is the first of `in the way`, `not cloned`, `local changes`,
`off its commit`, `ok`, from the same `_blocked` the refusal uses.
`sync_clone(clone, dry_run)` returns the steps (`clone` with the URL,
`checkout` with twelve digits) and raises the checkout's `SourceError`s.
`edit.remove` calls `_delete_clones` after deleting the checkout: each
non-dot entry under `plugins/<name>/` goes through `_delete` (a `delete`
change, or a problem and the entry left), then the directory is removed
if empty (not in a dry run; no change is listed for it). README and
`skills/tack/SKILL.md` say `remove` deletes plugin clones. Nothing else
calls the clone code.
