## Kickoff notes

Most of this chunk is runs, not code: units a and b run the real agents by
hand and record what they saw; their commits carry the docs those runs
correct. No test may run a real agent, and none is added that does.

directory, as `tools/agent_facts.py` makes one), never the real one. The
one exception is b's read of the real setup, which runs only the read-only
commands it lists. **The repository is public**: the report and the docs
name agent-owned marketplaces, versions and counts, never the maintainer's
own plugins, paths, account or hostname. A run that shows tack doing the
wrong thing is a finding. Fix it in the unit if the fix is small and a
stand-in test can pin it; otherwise stop with a partial report and say
what you saw.

### P0001-C13-a — Real agents (P0001 §6 *Real agents*)

**Build:**

- Run `uv run python tools/agent_facts.py` against the installed agents
  first, and record its result and both versions.
- In a scratch `HOME`: a local clone of
  `https://github.com/anthropics/claude-plugins-official`, and a manifest
  whose `git` source is that clone (its path), `skills = []`, selecting
  `skill-creator` (in the source) and one entry from another repository
  that has a 40-digit `sha`: pick a small repository, and name the entry
  and its kind (`url` or `git-subdir`) in the report. `tack sync`, then:
  `claude plugin list --json` shows both `@tack`, loaded from tack's
  marketplace; `codex plugin list --json` lists both.

  clone, `tack outdated`, `tack update`; Codex's copy of `skill-creator`
  has the change.
- `tack remove` of the source: both plugins uninstalled in both agents and
  tack's marketplace unregistered from both.
- Where a run disagrees with *Harness facts*, correct the fact (with the
  version it was seen in), and the stand-in in `tests/standin.py` if it
  models it. Update the plugin facts' "verified" lines to today's versions
  for what this run re-verified.

### P0001-C13-b — A real setup (P0001 §6 *A real setup*, #42)

**Build:**

- In a scratch `HOME`: hand-install a plugin from a local marketplace that
  isn't tack's (through `claude plugin marketplace add` and `install`,
  `codex plugin marketplace add` and `add`), with a manifest that selects
  nothing from it. `tack doctor --json` reports it as `unmanaged-plugin` in
  each harness, at the severity and location design.md gives.
- On the real setup, **read-only**, these commands and nothing else:
  `claude plugin list --json`, `claude plugin marketplace list --json`,
  `codex plugin list --json`, `codex plugin marketplace list --json`, and
  `uv run tack doctor --json`, all with stdin closed. Record which
  marketplaces the agents list plugins from, and whether `doctor` reports
  as `unmanaged-plugin` any plugin from a marketplace that is the agent's
  own. Design.md *Harness fields* defines the agent's own: plugins that
  come with the agent (bundled, built in) or from the user's account
  (claude.ai's synced ones), not ones the user installed. A marketplace
  the user added, `claude-plugins-official` among them, isn't the agent's
  own, and its plugins being reported is correct.
- Record in *Harness facts* the agent-owned marketplace names seen, with
  the versions, and for each built-in `ignore_marketplaces` default, seen
  or not seen (one not seen stays: it may appear only with plugins this
  setup lacks).
- An agent-owned marketplace seen and missing from the defaults is added to
  them: `config.py`, design.md's *Harness fields* table, README and
  `skills/tack/SKILL.md` where they list the defaults, with a test, and a
  decision-log entry recording what was seen. A user-added marketplace is
  never added.
- The pull request closes #42.

**Tests:** for an added default only: `doctor` doesn't report a plugin from
it (an existing `ignore_marketplaces` test extended).

**Done when:** the report has an *A real setup* section: the scratch run's

## Notes for the executor

- Pull request title: `docs: record P0001's completion runs (P0001-C13)`
  if nothing but docs changes, `fix: …` if a run brings a code fix, or
  `feat: …` if a default is added to `ignore_marketplaces`.
- `tools/agent_facts.py`'s `Agent` class and scratch-`HOME` setup are a
  model for a and b's runs; keep their scripts in your scratch directory,
  not in the repository.
- `config.Paths` reads `TACK_CONFIG`, `TACK_DATA` and `TACK_STATE`, then
  the `XDG_*_HOME` variables, before `HOME`: a shell that sets any of them
  would point a scratch run at real directories. Set all six under the
  scratch `HOME` for every scratch run (`CODEX_HOME` too, if it is set).
- Codex's `plugin list --json` nests its plugins; read its shape from
  *Harness facts* rather than guessing.
