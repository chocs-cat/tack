# Chunk P0001-C09 — the TUI's Plugins tab

**Goal:** the TUI shows plugins. A Plugins tab after Skills lists each
selected plugin and its state in each harness that takes plugins, grouped,
folded and sorted as Skills is but on its own; its detail says where a
plugin comes from, its version and description, and what `sync` would
report about it. The tabs are keyed `1`–`4`; the Sources detail names the
plugins a source selects and its changed plugins; each refresh lists each
agent's plugins once. That is delivery item D7, the last before D8 (plugins
from other repositories). Unit a fixes two small bugs in what C08 and C06
built: `add`'s git dry run against a leftover checkout (#49), and `doctor`'s
message for a source whose root is a file (#43).

### P0001-C09-a — `add`'s git dry run, and a root that is a file

**Build** (design.md *Adding and removing sources*, its last sentence,
pinned at this cut; *Source fields*; fixes #49 and #43):

- A dry run of a git source checks neither its skills nor its plugins,
  whatever tack's checkout of that name holds: `_skill_refusals` and
  `_plugin_refusals` both skip it (so the no-skills refusal's plugin list

- `doctor`'s finding for a source that isn't there says "has no directory

`tests/test_doctor_skills.py`, a path source whose `path` is a file, with

### P0001-C09-b — the Plugins tab, its keys, and one read of each agent

**Build** (design.md *The TUI*: the tab list, the tab keys, *Sorting*,
*Grouping*, *The Plugins tab*; *TUI fields*; *Plugin states*):

- A Plugins tab after Skills; the tabs run Skills, Plugins, Sources,
  Doctor, keyed `1`–`4`. The app still opens on Skills and never moves you.
- Its rows are `status`'s `plugins`: a plugin column, a source column
  while ungrouped, and a column per harness that takes plugins, in the
  order Skills shows them; `-` where a plugin doesn't go. States colored as
  *The Plugins tab* says.
- Sorting, grouping and folding as on Skills, with the plugin state order
  (conflict and collision, stale, disabled, unavailable, missing,
  installed, then not targeted), each held through a refresh and separate
  from Skills': `o`, `O`, `g`, `space`/`enter`, `←`/`h`, `→`/`l` and a
  header click act on the tab they're used on; `[tui] group_by_source` sets
  both tabs' grouping when the app opens. A group row for each source whose
  `plugins` isn't `[]`, in manifest order, with its count and, per harness,
  how many plugins aren't `installed` there by state in that order
  (`1 disabled, 1 missing`), colored as its worst. The sort and group
  actions show in the footer on both tabs and no other.
- With no plugin selected, the table is empty and the detail says so, and
  how to select one (*The Plugins tab*).
- Each refresh lists each agent's plugins once (its two `list` commands),
  shared by the Plugins tab and the audit (*The TUI*, pinned at this cut;
  the D7 note in the project). `status --json` and `doctor`'s output are
  unchanged, and `status` and `doctor` run alone still list what they did.

**Tests**, in `tests/test_tui.py`: the tab order and `1`–`4` (each key
shows its tab; the app opens on Skills). Every state rendered: for each of
`tests/test_status.py`'s `FIXTURES`, the Plugins rows' cells equal the
states `status` gives (import or move the fixtures; don't copy them). The
plugin column sort in a harness column, both directions, with a plugin that
doesn't go there last. Grouping: group rows and their summaries for two
sources selecting plugins and one selecting none (no row for it), a fold
held through `r`, `g` on Plugins leaving Skills grouped, and Skills' sort
leaving Plugins' alone. With no plugins: an empty table and the detail's
message. One read per refresh, on a manifest selecting a plugin for both
agents (with none selected, `status` lists nothing and the count already
holds): clear the stand-ins' call log, press `r`, settle, and each agent's
`plugin list` and `plugin marketplace list` ran exactly once
(review-checklist §1: count after the refresh, not after opening).

### P0001-C09-c — the details, the sync preview, and the docs

**Build** (design.md *The TUI*: *The Plugins tab*, the Sources bullet):

- A plugin's detail: its name, its source and that source's pin (a `path`
  source's directory), tack's copy if there is one, its version, its
  description (the first string `description` among its `plugin.json`
  files, read as `catalog.version` reads `version`, else its entry's, else
  none), and its state in each harness it targets, colored. For a plugin
  `sync` reports a problem about (one tack can't deploy, one from another
  repository, one whose files can't be read, a name two sources select),
  that problem's message as `sync` words it, from code `sync` also calls. A
  source's group row shows the source's detail, as on Skills.
- The Sources detail (and so a group row's) names the plugins a source
  selects after its skills, when it selects any; and gives its changed
  plugins (`plugins modified: a (1.0 -> 1.1), b`), its `plugins_error`,
  and "no selected skill or plugin changed" as `outdated`'s text does, from
  one function `cli._outdated_text` and the TUI both call.
- README.md and `skills/tack/SKILL.md`: the Plugins tab, the tab keys, and
  no "the TUI doesn't show plugins yet".

**Tests:** in `tests/test_tui.py` (or on `render` directly, as
`test_source_state` does): the detail of a plugin inside a path source and
a git source (source, pin or directory, copy, version, description from
`plugin.json` over the entry, and from the entry alone; each harness's
state); for an undeployable plugin, one from another repository, one whose
directory is gone, and a collided name, each from a path source whose state
is `ok`, the detail holds the problem a `sync` dry run reports for it,
compared with that run's message, not a literal (brief-checklist §5, §6:
`sync` holds other sources first, and the test, not the list, keeps the
two together). The Sources detail of a git source behind with a plugin modified,
added and removed, and with `plugins_error`, line for line what
`_outdated_text` prints for it; a plugin-only source's detail names its
plugins. The `s` preview on a manifest selecting a plugin lists `would run
claude plugin install …` and `would run codex plugin add …`.

**Done when:** those pass, `tests/test_examples.py`, `test_skill.py` and
the existing `outdated` text tests pass unchanged, and README and the skill
describe the tab.

## Out of scope

- Plugins from other repositories (D8): their detail gives the problem
  `sync` reports until then; the repository and commit come with D8.
- Settings for `plugins` or `ignore_marketplaces` (edited by hand).
- Acting on a plugin from the tab (no new key beyond `s`, which syncs as
  before).
- A version column, or a description in the table.
- #10, #17, and other open issues not named here.
